# 看盘页面设计：数据新鲜度与板块划分

写这份文档的原因很具体：页面上原来把**两种新鲜度的数据混在一起且不标注**——
"最新价"取的是日线的收盘价（可能是昨天），而旁边的分时图却是实时的，
用户没有任何线索判断哪个数字是几点钟的。数据能不能用，先取决于它有多新。

---

## 一、数据分四档

按"多久变一次"和"拿它要付什么代价"分档，每档对应一种刷新策略。

| 档位 | 数据 | 更新节奏 | 怎么拿 | 页面表现 |
|---|---|---|---|---|
| **实时**（秒级） | 最新价、涨跌幅、成交额 | 交易所每秒都在变 | 腾讯报价接口，一次可问多只 | 只在盯盘区显示，**标注抓取时刻**，交易时段每 30 秒自动刷 |
| **盘中**（分钟级） | 当日分时线（1 分钟 + 5/30/60 分钟聚合）、盘中提醒 | 每分钟一根 | 腾讯分时接口，**只给当天** | 分时图；打开时本地没有就现抓一次，交易时段跟随刷新 |
| **日终**（每天一次） | 日线、特征、状态、趋势分、关键带、仓位上限/止损、提醒、市场广度、涨跌榜 | 收盘后一次算完 | 本地 K 线 + 本地计算（15:05 之后） | 所有"结论类"数字都归这一档，**标注是哪一天的** |
| **按需**（手动触发） | 全市场同步、形态筛选、参数回测、影子因子体检、打包 | 你想跑就跑 | 本地计算 + 联网抓数 | 任务卡 + 按钮；结果标注"上次运行时间" |

两条判断原则：

1. **结论类数据必须走日终**。状态、因子分、仓位上限这些是"算出来的结论"，盘中半小时重算一次
   没有意义（状态机本身就是滞后的），反而会让同一个数字在同一分钟内变化，失去可追溯性。
2. **只有"事实类"数据才实时**。最新价、分时线是事实，市场没变它就不变；
   它们不需要任何计算，也就没有"算错"的风险。

### 交易时段

实时/盘中两档只在交易时段有意义：**09:30–11:30、13:00–15:00**（用 `trade_calendar` 判断交易日）。
非交易时段不自动刷新，页面直接显示"已收盘"，避免用陈旧数据假装实时。

## 二、页面板块

顶层是五个视图：**自选标的 / 市场与扫描 / 因子台账 / 参数回测 / 筛选池**。
前两个是"盯盘"的两种姿势，后两个是"复盘"的两种姿势——它们读的是同一份本地库，
但回答的问题完全不同：台账回答"我的结论是被谁拉过去的"，回测回答"这套参数到底有没有超额"。
每个视图内部仍按数据档位切成**带新鲜度徽章的板块**。

### 顶部：数据状态条（全局，常驻）

一行文字 + 徽章，回答"我现在看到的数据有多新"：

```
日线 2026-09-17 ✅当日   分时 11:05 ⏱盘中   特征 09-17 ✅   广度 09-16 ⚠差一天
上次日终 11:18   上次筛选 09-16 15:20
```

- 徽章三档：`实时/盘中`（绿）、`当日`（灰）、`陈旧`（橙，并说明差几天）
- 数据来自 `/api/freshness`，页面加载时拉一次，跑完任务后重拉

### 视图一：自选标的

| 板块 | 档位 | 内容 |
|---|---|---|
| **① 盯盘（实时）** | 实时 / 盘中 | 报价条（现价、涨跌幅、成交额、抓取时刻）+ 刷新按钮；分时图 |
| **② 日终结论（每天一次）** | 日终 | 顶部指标带（状态、趋势分、机会分、量比、仓位上限、止损、形态）；日K图（含**关键位置形态标记**，可开关）；关键带；因子贡献；本标的提醒 |
| **③ 市场（日终）** | 日终 | 涨跌家数、涨停跌停、中位数涨跌幅、成交额、涨跌分布；涨幅榜/跌幅榜 |
| **④ 扫描与运维（按需）** | 按需 | 任务卡（日终/同步/筛选/快照/分时）+ 日志；形态筛选结果 |

### 视图二：全市场

同一个页面里切过去，板块与上面 ③④ 一致（避免"同一份数据两个地方各画一遍"）。

### 视图三：因子台账

| 板块 | 档位 | 内容 |
|---|---|---|
| **① 在册因子** | 日终 | 每个因子的层/类别/权重/状态（生效·影子）/覆盖天数/IC5·IC20/最大相关/结论 |
| **② 影子因子** | 日终 | 只列 `status: shadow` 的因子：样本进度条（对照 20 个交易日）、与现有因子的相关性、IC、结论 |

数据来自 `factor_registry`（在册名单）与 `factor_contributions`（每天实际记了什么），
相关性与 IC 由 `promotion.factor_stats` 现算。**结论列直接把"够不够格转正"写在脸上**，
不让人自己对着三个阈值心算——阈值是规格里的准入条件，不是页面自己定的。

### 视图四：参数回测

| 板块 | 档位 | 内容 |
|---|---|---|
| **① 参数网格** | 按需 | 按 20 日净超额排序的组合表：信号数、胜率、均值、基准、净超额、平均回撤、年频次、**邻域表现**；当前配置高亮 |
| **② 怎么读** | 常驻 | 口径说明：先看超额、再看信号数、再看邻域是不是高原 |

页面读的是 `回测/回测结果-<时间戳>.json`（`run.py backtest` 与页面上的「跑一次回测」都会写），
**不为了看一眼结果重跑一遍回测**；按钮触发的重跑走的是页面任务队列，日志和别的任务一样实时显示。
markdown 报告仍然照旧写在 `回测/回测报告-<日期>.md`，两份并存：一份存档、一份给页面。

### 视图五：筛选池

| 板块 | 档位 | 内容 |
|---|---|---|
| **① 口径** | 日终 | 最近筛选日、回看窗口、至少命中几次、成交额门槛、上次扫描扫了多少只；外加一段"筛选池怎么来的" |
| **② 候选进池** | 日终 | 池外的票按证据排序：命中次数/涉及几个筛选日、命中形态、日均成交额、命中后 20 日超额、风险层；每行带「加入自选」 |
| **③ 池内现状** | 日终 | 观察池的票最近还有没有出现（没出现的单独标出来）、状态、风险层；每行带「移出」 |
| **④ 形态表现** | 回填后 | 每种形态的命中样本数、5/20 日均值与胜率（**绝对**收益），再后面三列是按交易日聚合的**超额 / t / 校正 p**：先按日取均值再算 t，并按形态个数做 Šidák 校正——同一天几十只票一起涨跌，按样本算误差棒会把噪声当结论；同时看 8 个形态，最好的那个本身就被挑过一遍 |

为什么要把这四块凑成一页：它们回答的是同一个人操心的问题——"我现在该看什么"。
候选清单来自 `candidates.build`（页面只读，不自己排序），表现来自 `screen.outcome_stats`（要回填过才有数）。

## 三、刷新策略（前端）

| 触发 | 行为 |
|---|---|
| 打开页面 | 拉 `/api/freshness` + 自选列表 + 当前标的日K；分时图按需现抓 |
| 交易时段每 30 秒 | 拉 `/api/quotes` 更新报价条；若正在看分时图，同时拉 `/api/intraday` |
| 页面切到后台 | 暂停自动刷新（`visibilitychange`），回来时立刻补一次 |
| 跑任务期间 | 沿用现有 `pollJobs`（1.5 秒轮询进度），任务结束后重拉新鲜度 + 相关数据 |
| 手动 | 报价条上的刷新按钮；任务卡按钮 |

切到分时图时**不会**去抓日线或重算特征——那些是日终的活，盘中重复算既慢又没意义。

## 四、落地顺序

1. 后端：`/api/freshness`（数据新鲜度总览）、`/api/quotes`（批量实时报价）
2. 后端：报价适配器补 `pct_chg` / `amount`（腾讯报价接口本来就给，之前只取了价格）
3. 前端：顶部状态条 + 四个板块标题（带徽章）
4. 前端：盯盘区报价条 + 交易时段 30 秒刷新 + 切后台暂停
5. 测试：接口单测 + 页面结构静态自检（沿用 `tests/test_web_page.py` 的做法）

### 已落地（2026-09-19 改版）

1. 后端：`/api/factors`（台账 + 体检）、`/api/backtest`（最近一次回测），都是只读、不抛异常
2. 后端：回测结果结构化落盘 `回测/回测结果-*.json`，页面任务队列新增 `backtest` 按钮
3. 前端：设计令牌重做（冷灰中性色 + 单一蓝、等宽数字、更紧的圆角与分层阴影）
4. 前端：顶部 58px 常驻栏（品牌 + 数据状态条 + 视图切换 + 主题开关），左栏只留自选清单
5. 前端：新增「因子台账」「参数回测」「筛选池」三个视图（含空态、加载骨架、错误态）

### 又一批（2026-09-19 晚）

1. **状态条改成真滚动**：两侧淡出提示可横向滚、细滚动条、鼠标滚轮也能横滚
2. **深色主题**（默认）：`[data-theme="dark"]` 覆盖整套令牌，图表颜色从 CSS 变量读，
   切主题时重画一次；A 股红涨绿跌口径不变，只把明度提上来
3. **筛选池**：候选进池 / 池内现状 / 形态表现三块 + 出池标记（连续未命中、成交额跌破门槛），
  只提示不动作、按角色与新鲜度设闸门

### 再一批（2026-09-19 傍晚）：形态层重写

1. **形态层加了组合形态与趋势前提**：10 个组合形态（早晨之星/黄昏之星、看涨/看跌孕线、
   乌云盖顶/刺透、平底/平顶、红三兵/三只乌鸦）；锤子与上吊线、流星与倒锤星按
   "前面是涨还是跌"分开命名；阈值集中到 `candles.THRESHOLDS`
2. **图上标记分三类**：三角 = 反转确认，**菱形 = 组合形态**，小圆点 = 其他关键位形态；
   悬停一起给出"是什么形态"和"长在什么关键位置"；提示框改成先量真实宽高再夹位置
   （多了两行之后，靠右的 K 线提示会被画布边缘切掉半句）
3. **关键位形态提醒**：`KEY_PATTERN_STRONG`（P1，反转 + 放量）、
   `KEY_PATTERN`（P2，组合形态或放量单根）。三道门槛（状态前提 / 量能 / 按信号冷却）
   都是量出来的，实测每只每 250 个交易日约 10 次

### 再一批（2026-09-19 深夜）

1. **K 线形态标记**：日K图新增「形态」开关，只画**关键位置上的明显形态**
   （20 日区间上下沿 / 破 20 日高或低 / 贴或穿越均线 / 20 日极值分型 × 反转确认或放量实体），
   红三角=反转向上、绿三角=反转向下、小圆点=其他关键位置形态，悬停给出原因。
   口径在 `candles.marks` / `candles.key_position`，页面只负责画，不自己发明判定
2. **形态统计加了显著性与多重检验校正**：④ 形态表现新增「按日超额 / t / 校正 p」三列，
   先按交易日聚合再算 t，并按形态个数做 Šidák 校正（`collector/stats.py`）
3. **摆动结构进了因子台账（影子）**：`swing_state` / `dist_to_swing_low`，
   最近结构低点还参与风险层止损候选（取更近者，只收紧不放宽）
